# Aramis Internal Clinical Report Content

Status: approved target contract; implementation follows the completed report
contract review.

Purpose: an internal audit record for one Aramis research-draft prediction
operation. It records the incoming scan context, usable XRD evidence,
reliability, final target-side result, and the immutable model artifact used.
It is not a public clinical report and is not for autonomous diagnosis.

## Top-Level Structure

```yaml
output_type: aramis_internal_clinical_report
report_version: "0.1"
reference_doc: ./docs/modeling/internal_clinical_report_content_v0_1.md

report_id: GENERATED_UNIQUE_ID
created_at: "2026-07-13T14:11:00+02:00"
analysis_author: OPERATOR_OR_ANALYST

model:
  id: MODEL_ARTIFACT_ID
  name: M2Q
  version: MODEL_ARTIFACT_VERSION
  artifact_sha256: SHA256

prediction_config: {}
scan_metadata: {}
evidence: {}
final_prediction: {}
```

`report_id` is generated by Aramis and shared with the associated external
report. `created_at` is an ISO 8601 Europe/Paris timestamp with a numeric UTC
offset. Every numerical value is rounded to five decimal places. Every binary
field uses `true` or `false`.

## Prediction Configuration Snapshot

`prediction_config` is a structured copy of the caller-supplied request. It
appears as a JSON object in the JSON report and as the equivalent mapping in
the YAML report. It does not include duplicated model parameters.

```yaml
prediction_config:
  run:
    analysis_author: OPERATOR_OR_ANALYST
  patient:
    patient_id: PATIENT_ID
    target_side: left
```

## Scan Metadata

`scan_metadata` contains all incoming patient, clinical-context, technical, and
post-preprocessing measurement-summary fields. The target side is supplied by
the caller; the contralateral side is inferred when measurements for the other
breast are present and is therefore not serialized as a separate side label.

```yaml
scan_metadata:
  patient_id: PATIENT_ID
  target_side: left
  patient_age: 53.0
  patient_age_available: true

  session_id: H5_SESSION_ID
  scan_date_time: "2026-07-13T13:58:22+02:00"
  operator_id: opt123455
  hardware_version: "human-1 v1.2.0"
  eoscan_version: unknown
  experimental_protocol_version: human1_protocol_v0.3

  mammography_suspicious_field: upper outer quadrant
  mammography_conclusion: unknown

  measurement_summary:
    target_valid_measurements: 3
    contralateral_present: true
    contralateral_valid_measurements: 3
```

At the current development stage, unavailable optional H5 metadata is written
as the string `unknown`; its absence does not stop prediction. Technical fields
required by preprocessing, including container schema/format, patient and
specimen IDs, side, PONI, and thickness metadata, remain mandatory.

`mammography_suspicious_field` and `mammography_conclusion` are report-only
clinical context. They are not preprocessing inputs, model features, or labels.

## Evidence

`evidence` contains computed values for this scan. It contains neither fitted
estimator objects nor model coefficients, weights, raw feature rows, or
standalone age/symmetry models.

```yaml
evidence:
  target_profile:
    available: true
    profile_p_cancer: 0.63482
    measurement_p_cancer:
      - 0.62105
      - 0.64799
      - 0.63545

  contralateral_profile:
    available: true
    profile_p_cancer: 0.28851
    measurement_p_cancer:
      - 0.27211
      - 0.30407
      - 0.28936

  symmetry:
    available: true
    selected_features:
      sk_wasserstein_distance_full_q2: 0.00106
      sk_weightedrms1: 0.00028
      sk_weightedrms2: 0.00031
      sk_mean_peak_value_abs_delta: 0.00844

  reliability:
    level: high
    reason: at least 3 valid measurements on target and contralateral breasts
```

`contralateral_present` means that at least one valid contralateral measurement
remains after preprocessing. `symmetry.available` means that the selected SK
target-vs-contralateral features were actually calculated. The fields are not
interchangeable.

The target and contralateral `profile_p_cancer` values are first-layer LR1
evidence only. The contralateral value is internal-only and does not replace the
final target-side decision-support result.

Only the selected SK Core4 values used by M2Q are included in
`symmetry.selected_features`.

## Final Prediction

```yaml
final_prediction:
  p_cancer: 0.59489
  decision_threshold_id: target_sensitivity_0.95
  decision_threshold: 0.32787
  suggested_class: CANCER
```

`final_prediction` is a result, not a serialized final-model object. The
training output YAML under `model_registry` remains the source of truth for
feature schema, regularization, threshold derivation, evaluation metrics,
coefficients, and training configuration. The model joblib remains executable.

## Explicit Exclusions

Internal report does not contain:

```text
contralateral_side
profile_statistics
intermediate_models
feature_row
model coefficients or weights
training configuration
standalone age-only or symmetry-only scores
filesystem paths
provenance block
outputs block
```
